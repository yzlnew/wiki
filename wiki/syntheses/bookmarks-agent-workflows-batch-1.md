## Summary

这一批链接围绕 Claude Code 的使用方式、agent 能力封装、上下文工程、长任务运行结构，以及深度研究和 reasoning 任务的组织方式展开。整体上看，材料的共同指向不是“更聪明的单条 prompt”，而是“更可靠的工作流骨架”。

## Key Claims

- 这些资料共同把“agent”定义为一套可运营的系统，而不是一次性对话。
- slash commands、skills 和 setup 指南说明入口设计与能力封装已经是 agent 使用体验的一部分。
- harness、context engineering 和 deep research 相关材料强调长任务、状态管理和上下文控制的重要性。
- reasoning / task set / benchmark 相关链接显示，这一主题还关注如何把工作流和可测量的产出质量绑定起来。

## Evidence Notes

- `Slash Commands`、`Claude Code Cheat Sheet`、`My Claude Code Setup` 和 Boris Cherny 的帖子都在围绕 Claude Code 的日常使用与配置方式展开。
- `Agent Skills` 明确把技能描述成可复用的能力单元，这和“把复杂任务拆成模块化入口”的思路一致。
- `Harness design for long-running application development` 和 `AI代理的上下文工程...` 都在强调长任务、上下文和运行时结构，而不是只讨论 prompt 文本。
- `GPT 4.1 Prompting Guide`、`The Differences between Deep Research...` 和 `o1 isn’t a chat model` 把提示、研究和 reasoning 放在同一个工作流问题域里看。
- `Open-Reasoning-Tasks` 与 `Bespoke-Stratos-32B` 表明这批资料也在关注 reasoning 任务的评测和训练侧基础设施。
